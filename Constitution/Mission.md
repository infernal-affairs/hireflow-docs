# HireFlow Mission

> 状态：基线（v1.0）  
> 最后更新：2026-10-29  
> 维护规则：关键变更先确认、再修改，并记录到 `DECISIONS.md`。

## 项目愿景

HireFlow 是一个用于求职与招聘协作的全栈练习项目。项目的首要目的不是堆叠功能，而是通过一条真实、可运行、可演示的业务闭环，把 Java、Spring Boot、MySQL、Vue 和前后端联调的理论知识转化为工程实践。

完成项目后，学习者应能独立说明自己做过什么、为什么这样设计、遇到什么问题，以及如何验证功能正确性。

## 目标受众

- 主要用户：准备投递杭州中小公司 Java 全栈岗位的计算机专业应届生。
- 直接受益者：需要从“看得懂教程”过渡到“能独立实现功能”的学习者。
- 间接受众：需要快速了解项目背景、技术取舍和演示流程的面试官。

## 要解决的核心问题

1. 学习时间紧，无法从零做一个大而全的项目。
2. 学过 Java、Spring Boot、MySQL 和 Vue，但没有走通过完整开发链路。
3. 能理解示例代码，却缺少独立设计、实现、排错和复盘经验。
4. 面试时容易只背概念，无法把技术选择和业务场景连接起来。

## 核心业务闭环

招聘方发布职位 → 求职者完善资料并投递 → 招聘方查看投递并推进状态 → 求职者查看进度。

## 成功标准

- 能独立完成注册登录、职位发布、职位投递和投递状态处理。
- 能解释数据库表、接口、鉴权、权限边界和状态流转的设计取舍。
- 能使用 Git 小步提交，并展示清晰的开发过程。
- 能通过编译、启动和手工接口验证完成双角色主流程演示；自动化测试按独立决策处理。
- 能用自己的语言回答项目追问，而不是复述代码。

## 范围边界

优先完成可运行的核心闭环。以下内容不作为第一版目标：

- 微服务拆分、消息队列、Redis、在线聊天和文件上传。
- 复杂推荐算法、完整后台审核体系和企业认证。
- 生产级高可用、完整 CI/CD 和复杂部署方案。

范围可以调整，但必须先评估对核心闭环、学习目标和时间成本的影响，并记录决策。

## 学习原则

- 以亲手实现为主，示例用于展示模式，而不是替代思考。
- 先让功能可运行，再解释设计，再做测试和复盘。
- 每个模块都要留下可验证结果、学习笔记和 Git 提交。
- 不把“功能更多”当作成功，优先保证链路完整和表达清楚。

## 带练工作协议

每次开始一项工作前，必须先说明：

1. 本项工作的目标和验收标准。
2. 是否需要新增依赖；如需要，说明依赖名称、作用、版本确定方式和引入时机。
3. 本项工作依据的 Mission、TechStack、RoadMap 或 DECISIONS 条目。
4. 关键设计的分析过程，而不是只给最终答案。

示例使用规则：

- 只有出现新概念或新模式时，才提供完整示例。
- 示例中的关键语句前要有简短注释，说明“做什么”和“为什么”。
- 示例后要解释关键取舍、边界和常见错误。
- 当后续任务与已示范内容是同一类工作时，不再直接给完整实现；应给出字段分析、约束判断、检查清单和必要提示，由学习者先独立设计。
- 学习者完成后，由教练逐项审查，再决定是否需要局部修正。
- 每次交付前必须验证，并把结果、踩坑和面试问答沉淀到学习笔记。
