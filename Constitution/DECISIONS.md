# HireFlow Decision Log

> 本文采用追加式记录。旧决策不覆盖，新的结论通过新条目说明。  
> 关键变更必须先评估影响，经确认后再更新 Constitution。

## 2026-10-28：项目定位与目标受众

- 背景：学习者只有约 20 天准备时间，目标是杭州中小公司 Java 全栈岗位。
- 选项：完整商城、博客、任务管理、招聘投递系统。
- 结论：选择 HireFlow 招聘投递系统，只做双角色核心闭环。
- 影响：业务熟悉、链路完整；主动放弃大而全功能。

## 2026-10-28：项目技术栈

- 背景：需要覆盖杭州中小公司常见技术栈，并控制学习成本。
- 选项：Java 17/21、Spring Security/拦截器、MyBatis-Plus/JPA、Vue/React。
- 结论：Java 21、Spring Boot 3.4.x、MyBatis-Plus、JWT + 拦截器、Vue 3 + TypeScript。
- 影响：兼顾面试相关性与开发速度；不引入 Spring Security、Redis 和 Docker。

## 2026-10-28：仓库边界

- 背景：希望本地和 GitHub 上都实现前后端分离，同时保留宪法与文档。
- 选项：单仓库 Monorepo、前后端双仓库、三个独立仓库。
- 结论：使用 `backend`、`frontend`、`docs` 三个独立 Git 仓库；外层工作区不是 Git 仓库。
- 影响：仓库职责清晰；代价是需要分别提交和推送。

## 2026-10-28：Constitution 治理

- 背景：关键决策需要可追溯，并支持边实践边调整。
- 选项：自由编辑、严格 ADR、确认后更新并追加记录。
- 结论：关键变更先说明影响并确认，更新 Constitution，再追加到本文件。
- 影响：增加少量文档成本，换取清晰的共识和面试复盘材料。

## 2026-10-28：RoadMap 粒度

- 背景：实践周期紧，不能假设所有阶段都严格按日期完成。
- 结论：采用“里程碑 + 可验证产出 + 依赖 + 状态”的活文档，允许按可验证性重排。
- 影响：优先保证可运行切片，不把路线图变成逐日任务表。

## 2026-10-29：带练与示例使用规则

- 背景：同类建表任务连续提供完整 SQL 示例，削弱了学习者独立分析字段和约束的机会，也不符合 Mission 中“示例用于展示模式”的原则。
- 选项：继续提供完整示例、只给口头提示、将带练协议写入 Constitution 并严格执行。
- 结论：采用第三种。新概念首次出现时提供带注释示例；同类任务改为分析框架、约束清单和提示，由学习者先实现，再审查。
- 影响：单次推进可能稍慢，但能保证独立设计、编码和面试表达的训练效果。每项工作开始前必须进行目标、依赖、依据和验收说明。

## 2026-10-29：当前阶段忽略自动化测试

- 背景：实践时间紧迫，需要优先完成可运行的业务功能开发。
- 选项：逐项补测、暂时忽略测试、永久取消测试。
- 结论：当前开发阶段暂时忽略自动化测试，按正常功能开发流程推进；保留 JUnit 5 和 MockMvc 依赖，测试配置不在本轮删除。
- 影响：减少基础类测试带来的短期工作量。功能验收改为编译、启动和手工接口验证，不能将“未测试”表述为“测试通过”；后续是否补测另行决策。

## 2026-10-29：数据库、响应与分层规范

- 背景：M1 开始实现数据库表、统一响应和经典后端分层，需要把已经验证的约定固化为基线。
- 选项：只保留口头约定、写入 Constitution、写入每个模块临时笔记。
- 结论：写入 Constitution，并在 M1 学习笔记中展开解释。
- 关键约定：
  - 基础表从 `users`、`candidate_profiles`、`companies` 开始，后续按依赖顺序增加 `company_members`、`jobs`、`applications`。
  - 一对一资料表直接用共享主键 `user_id`；公司展示名称不唯一，归一化名称唯一。
  - 接口返回 `{ code, message, data }`；业务成功码为 `0`，HTTP 成功状态码为 `200/201`。
  - `ApiResponse` 使用普通 Java class、不可变字段、getter 和静态工厂方法。
  - Controller 不直接调用 Mapper；业务规则和事务放在 Service；Entity、DTO、VO 分离。
- 影响：基础结构更明确，后续表、接口和代码需要遵守这些约定；调整时必须同步更新 Constitution。
