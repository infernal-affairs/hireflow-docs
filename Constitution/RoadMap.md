# HireFlow RoadMap

> 状态：活文档（持续更新）  
> 最后更新：2026-10-29  
> 维护规则：阶段按可验证性推进，可以重排；具体任务在 `TASKS.md` 跟踪。

## 使用方式

RoadMap 只管理阶段目标、依赖和验收条件，不绑定日期，也不要求机械按顺序完成。实践紧迫时，优先选择能形成端到端验证的关键切片。

一次只推进一个可验收切片。里程碑完成必须同时具备：

1. 可运行结果。
2. 关键自动化测试或手工验证记录。
3. 对应学习笔记。
4. Git 提交。

## 当前阶段性取舍

- 2026-10-29：因实践时间紧张，整个项目当前阶段先忽略自动化测试，按正常功能开发流程推进。
- 功能完成以编译、启动和手工接口验证为准；不能把“未执行测试”描述为“测试通过”。
- 测试相关内容不阻塞当前开发，后续如需补测再单独评估。

## 推荐优先路线

环境与宪法 → 数据库与基础工程 → 登录鉴权纵向切片 → 公司成员 → 职位 → 投递 → 测试 → 面试材料。

如果时间紧张，可以优先保证“登录 → 职位 → 投递”主链路，再补充公司成员的高级权限场景。
